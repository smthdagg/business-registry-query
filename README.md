# 工商企业聚合信息查询系统

> **Business Registry Query System** —— 聚合 88查 · 天眼查 · 风鸟 · 爱企查 的个人自用工商信息查询平台
>
> [English Documentation](README_EN.md) | 中文说明（本页）

一次搜索、多源并行、自动合并去重、逐字段标注来源。参照天眼查的交互重写了整套界面与数据结构：搜索结果可点击穿透、公司档案分区分明、查老板按人员档案精确区分同名、关联图谱覆盖法人/股东/高管/投资/分支机构。

## 功能特性

### 查询能力

| 能力 | 说明 |
|---|---|
| **六角度搜索** | 综合 / 企业名 / 法人 / 股东 / 信用代码 / 电话，任选角度 |
| **四源聚合** | 88查、天眼查、风鸟、爱企查并行查询，按风鸟 > 88查 > 天眼查 > 爱企查优先级合并 |
| **合并去重** | 统一社会信用代码优先归一，其次企业名；重复企业做字段级互补，记录 `sources` 来源列表 |
| **查老板** | 按人名搜索返回"人员条目"而非公司噪声：风鸟按人员档案精确分组同名人员（独立 personId），支持按任职企业所在省份筛选，点选查看名下企业（含职务） |
| **公司档案** | 与天眼查同构的分区展示：基本信息 / 股东信息（含持股比例）/ 主要人员 / 对外投资 / 分支机构，跨源比对补全字段 |
| **关联图谱** | Canvas 力导向图：法人、股东、高管、对外投资、分支机构五类关系，可多跳展开（深度 ≤ 3、节点 ≤ 60），按节点记源 |
| **两级筛选** | 结果页按 省→市、行业门类→细类 级联筛选，另有经营状态筛选 |
| **省份直查** | 查老板支持省级行政区代码（regionId）请求级过滤，如 340000=安徽 |

### 系统能力

| 能力 | 说明 |
|---|---|
| **批量查询** | 每任务最多 500 行，支持角度前缀（如 `法人:张三`），后台队列执行、任务中心看进度、可取消 |
| **多格式导出** | CSV / XLSX / JSON；导出内容内置公式注入防护 |
| **监控名单** | 收录关注企业，一键复查，记录状态变化次数 |
| **历史与日志** | 查询历史（可删除/清空）+ 操作日志（登录/查询/档案/任务/设置，仅管理员可见） |
| **角色分离** | 管理员 / 普通会员两级账号；设置与日志仅管理员可见 |
| **账号安全** | PBKDF2-SHA256（20 万次迭代）口令哈希、HMAC-SHA256 签名会话、连续 5 次失败锁定 60 秒 |
| **Cookie 管理** | 网页端在线管理（实时生效），支持 Netscape / JSON / Header 字符串 / cURL 四种格式文件导入；后台自动保活 |
| **浏览器降级** | 可选 Camoufox 指纹浏览器通道：Cookie 风控时自动走页面上下文调用（默认关闭） |
| **双语文档** | 中文 / English 双语说明 |

## 系统架构

```
┌──────────────────────────────────────────────────────┐
│  浏览器 SPA（原生 JS，hash 路由，无构建依赖）             │
│  搜索 / 查老板 / 公司页 / 人员页 / 图谱 / 批量 / 设置      │
└──────────────────────┬───────────────────────────────┘
                       │ fetch /api/*
┌──────────────────────▼───────────────────────────────┐
│  FastAPI（app/main.py）                               │
│  ├─ auth.py       登录 / 会话 / 限速 / 角色             │
│  ├─ routes.py     查询 / 档案 / 人员 / 监控 / 批量 / 管理 │
│  └─ services/                                          │
│      ├─ aggregate.py  聚合调度：并行调用 + 合并去重       │
│      ├─ search.py     单源执行：缓存 / 历史 / 人名过滤   │
│      ├─ relation.py   关联图谱引擎（按节点记源）         │
│      ├─ profile.py    公司档案：分区明细 + 跨源比对      │
│      ├─ worker.py     批量任务后台队列                  │
│      └─ exporter.py   CSV/XLSX/JSON 导出（防注入）      │
├──────────────────────────────────────────────────────┤
│  sources/ 数据源适配器                                  │
│  ├─ cha88.py       88查 MTOP（token 签名 + 自动重试）    │
│  ├─ tianyancha.py  天眼查移动站接口                     │
│  ├─ riskbird.py    风鸟（搜索 / 人员分组 / 档案 / 任职）  │
│  ├─ aiqicha.py     爱企查                               │
│  ├─ mock.py        演示数据（无 Cookie 体验全功能）       │
│  └─ cookies.py     Cookie 权威存储（data/cookies.json） │
├──────────────────────────────────────────────────────┤
│  SQLite（WAL）：config / cache / history / tasks /      │
│  watchlist / logs / users                              │
└──────────────────────────────────────────────────────┘
```

**技术栈**：Python 3.12 · FastAPI · Uvicorn · SQLite（WAL）· 原生 JS SPA · Canvas 力导向图 · openpyxl · Docker

**设计要点**

- **源适配器统一接口**：每个源声明支持的角度（angles）、策略（strategies）、最小请求间隔（minInterval），聚合层据此并行调度，单源失败不影响整体
- **缓存键**：`源|角度|关键词|p:人名|r:省代码|l:条数`，避免重复消耗配额
- **人名过滤**：法人/股东角度结果经 `record_person_hit` 校验（法定代表人 / 自然人股东 / matchType 判定），剔除"公司名含人名"的噪声

## 快速开始

### 方式一：本地直接运行

```bash
# 1. 安装依赖（推荐 uv，也可用 pip）
uv venv && uv pip install -r requirements.txt

# 2. 准备配置
cp .env.example .env        # 按需填写 Cookie 与口令（见下文）

# 3. 启动
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000

# 4. 打开 http://127.0.0.1:8000
```

未配置任何 Cookie 时系统使用内置 **Mock 演示源**，可完整体验全部功能（数据为虚构样本）。

### 方式二：Docker 运行

```bash
cp .env.example .env        # 填写配置
docker compose up -d --build
# 访问 http://127.0.0.1:8000
```

数据（数据库 / Cookie / 会话密钥）持久化在 `./data` 卷，重建容器不丢失。

### 方式三：VPS 部署

```bash
# 服务器需已安装 Docker 与 compose 插件
# 国内 VPS 建议先配置镜像加速（/etc/docker/daemon.json 的 registry-mirrors）

rsync -av --exclude .venv --exclude data/app.db* --exclude .git \
      --exclude __pycache__ --exclude tests \
      app scripts requirements.txt Dockerfile docker-compose.yml .env.example \
      user@your-vps:~/business-query/

ssh user@your-vps
cd ~/business-query
cp .env.example .env && nano .env     # 至少设置 ADMIN_PASSWORD
sudo docker compose up -d --build
```

记得在云厂商安全组放行对应端口；生产建议套 Nginx/Caddy 反代并启用 HTTPS。

## 配置说明

所有配置均在 `.env`（参考 `.env.example`）；数据源与 Cookie 也可在网页"设置"里在线管理（实时生效，存储于 `data/cookies.json`）。

| 变量 | 说明 | 默认 |
|---|---|---|
| `ADMIN_PASSWORD` | 管理员初始口令（首次启动自动落库为 admin 账号） | 空（不启用登录） |
| `MEMBER_PASSWORD` | 普通会员初始口令（落库为 member 账号） | 空 |
| `DATA_SOURCE` | 默认数据源：`all` 聚合 / `rb` / `c88` / `tyc` / `aqc` | `all` |
| `TYC_COOKIE` | 天眼查 Cookie | 空 |
| `AQC_COOKIE` | 爱企查 Cookie | 空 |
| `RB_COOKIE` | 风鸟 Cookie（SVIP 效果最佳） | 空 |
| `CHA88_COOKIE` | 88查 Cookie（免账号也可用，但有滑块风控） | 空 |
| `TYC_DELAY` | 天眼查请求最小间隔（秒） | `2` |
| `COOKIE_KEEPALIVE_MIN` | Cookie 保活循环间隔（分钟） | `30` |
| `BROWSER_FALLBACK` | 风控时启用 Camoufox 浏览器降级 | `false` |
| `BROWSER_HEADLESS` | 浏览器无头模式 | `true` |
| `SECRET_KEY` | 会话签名密钥（不设则自动生成 `data/secret.key`） | 自动 |
| `DATA_DIR` | 数据目录 | `data` |

> **登录开关**：`ADMIN_PASSWORD` / `MEMBER_PASSWORD` 任一非空即启用登录。不设置则任何访客直接以管理员身份使用（仅限本机自用场景）。

## Cookie 获取与导入

### 各源获取方式

| 数据源 | 获取方法 | 说明 |
|---|---|---|
| **风鸟** | 浏览器登录 [riskbird.com](https://www.riskbird.com) → F12 → Network → 复制任意请求的 Cookie 头 | SVIP 账号字段最全（人员分组 / 股东 / 对外投资明细）；游客配额极少 |
| **天眼查** | 登录 [m.tianyancha.com](https://m.tianyancha.com) → 同上复制 Cookie | 免费单页 5 条为接口硬限制 |
| **88查** | 打开 [88cha.com/search](http://88cha.com/search) 随便搜一次 → 复制 Cookie | 免账号，匿名有滑块风控，失效较快 |
| **爱企查** | 登录 [aiqicha.baidu.com](https://aiqicha.baidu.com) → 复制 Cookie | 免登录配额极低；登录态搜索接口偶发改版返回空 |

### 网页导入（推荐）

设置 → 数据源与 Cookie → **导入 Cookie 文件**，支持四种格式（自动识别、自动格式化）：

1. **Netscape**：浏览器插件导出的 `cookies.txt`
2. **JSON**：EditThisCookie 等插件导出的 JSON 数组
3. **Header 字符串**：直接粘贴 `k1=v1; k2=v2; ...`
4. **cURL 命令**：从 DevTools "Copy as cURL" 复制的整条命令

导入后立即生效，无需重启。

## 使用教程

### 1. 综合搜索与筛选

1. 首页输入关键词（企业名 / 人名 / 信用代码 / 电话），选择角度后点"查 询"
2. 默认走**聚合查询**：四个源并行请求，顶部芯片显示各源状态（条数 / 耗时 / 跳过原因）
3. 结果表中：
   - **公司行**：点击公司名进档案；"关联"按钮一键生成该企业的关联图谱
   - **👤 人员行**（法人 / 综合角度）：显示同名人员分组，"名下企业"直达人员页
4. 结果页顶部筛选栏：**省份 → 城市**、**行业门类 → 细类**、经营状态，级联过滤当前结果
5. 历史查询芯片可一键重查

### 2. 查老板（人名搜人）

1. 顶部导航"查老板"（或搜索页切"法人"角度）→ 输入人名 + 选择省份 → 查询
2. 返回**同名人员分组**：每组是独立的自然人档案（风鸟 personId 精确区分），显示任职企业数、地区分布、最大企业
3. 点任一分组 → 该人**名下全部企业**（法定代表人 / 股东 / 高管身份合并，带职务与持股比例）
4. 页内可再换省份重新过滤；仅一组命中时自动直达该人员

> 与其他平台"搜法人出来一堆公司名"不同：这里返回的是**人**，同名不同人绝不混淆。

### 3. 公司档案

- 从任意搜索结果点公司名进入，分区与天眼查一致：
  - **基本信息**：信用代码、法人、注册资本、成立日期、经营状态、注册地址、经营范围、联系电话等
  - **股东信息**：股东名、**持股比例**、认缴出资（跨源互补）
  - **主要人员**：高管名单
  - **对外投资 / 分支机构**：明细列表（风鸟 SVIP 口径最全）
- 每个字段标注来源；"在图谱中查看"按钮一键生成关系图

### 4. 关联图谱

1. 公司页 / 搜索结果点"关联"，或导航"关联图谱"输入企业名
2. 自动展开：**同法人 → 股东 → 高管 → 对外投资 → 分支机构**，多跳扩展（深度 ≤ 3、节点 ≤ 60）
3. 节点按类型着色、按源标注；支持拖拽、缩放；点节点可看名下企业或继续展开

### 5. 批量查询与导出

1. "批量查询"页每行一个关键词，最多 500 行；支持角度前缀：
   ```
   法人:张三
   苏胜
   91340000MA2XXXXXXX
   ```
2. 提交后进入后台队列，"任务中心"看进度 / 取消 / 查看结果
3. 结果支持导出 **CSV / XLSX / JSON**（导出内容已做电子表格公式注入防护）

### 6. 监控名单

公司页点"加入监控"（或监控页手动添加）→ 名单页一键"复查" → 记录最近状态与变化次数。适合盯投标对手、关联方状态变动。

### 7. 历史与日志

- **查询历史**：搜索页侧栏展示最近记录，可单条删除 / 一键清空
- **操作日志**（仅管理员）：设置 → 操作日志，记录登录（含失败与限速）、查询、档案查看、任务、设置变更、监控操作

### 8. 设置与账号管理

- **数据源与 Cookie**：切换默认源、在线更新 / 清除各源 Cookie、导入 Cookie 文件、连通性探测
- **修改密码**：验证旧密码后设置新口令（≥ 6 位）
- **人员管理**（管理员）：新建 admin / member 账号、重置任意账号密码、调整角色、删除账号
- **操作日志**（管理员）：查看与清空

## 常见问题 FAQ

**Q：为什么法人搜索结果里既有"人员"又有"公司"？**
综合 / 法人角度会合并"人员条目"（👤 开头）与"法人匹配公司"。人员条目来自风鸟人员档案分组，是最精确的查老板口径；公司行来自天眼查 matchType=法定代表人匹配。

**Q：天眼查每次只有 5 条？**
天眼查移动站接口单页 5 条为硬限制，本系统不做绕过，只做聚合互补。

**Q：爱企查显示 0 条 / 跳过？**
爱企查搜索接口对登录态偶发返回空（站点改版）。不影响其他源，会在源状态芯片中如实标注。

**Q：风鸟报"配额已用尽（游客/登录）"？**
游客配额极少；请在网页设置里更新 SVIP 账号的 Cookie。每日配额次日重置。

**Q：Cookie 多久失效？**
各源风控节奏不同（88查最快）。系统内置 30 分钟保活循环；失效时对应源会在结果芯片显示原因，按提示更新即可。

**Q：忘记管理员密码？**
由另一管理员账号在"人员管理"重置；或在服务器上停止服务后删除 `data/app.db`（会清空历史/日志/账号，重启后按 `.env` 重新播种）。
